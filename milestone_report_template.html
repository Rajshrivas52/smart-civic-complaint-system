Executive Summary & Problem Statement

Municipal complaint handling mechanisms in urban centers predominantly rely on fragmented walk-in or manual procedures, resulting in delayed prioritization, lack of citizen visibility, unverified closures, and record duplication. The AI-Enabled Civic Issue Reporting and Resolution Management System delivers a unified, role-governed web application connecting citizens, departmental response teams (Road Maintenance, Sanitation, Water Works, Street Lighting), and administrative leadership. In this Milestone 4 phase, the platform has completed the core lifecycle: multi-role authentication & Google OAuth 2.0 with role onboarding, automated sequential complaint identification (SC-2026-XXXX), AI-driven heuristic classification & urgency scoring, multipart media evidence ingestion, department SLA computation, and in-app status change notifications.

Core Technical Capabilities Implemented in Milestone 4

1. Auto-Sequenced Complaint Lifecycle complaintController.js
Issues filed through the API are assigned atomic, human-readable IDs formatted as SC-YYYY-XXXX. The system parses issue categories (e.g., Pothole, Water Leakage, Garbage) and automatically assigns jurisdiction to the responsible municipal department. Each state update generates an immutable timeline entry recording timestamp, actor, status delta, and remarks.
2. Dual Authentication with Role Onboarding authController.js
The platform provides standard JWT-based email/password authentication backed by bcrypt hashing alongside Google OAuth 2.0. Users authenticating via Google OAuth are routed through a dedicated onboarding modal (GoogleRoleModal.jsx) enabling explicit selection between Citizen, Department Officer, or Administrator privileges before session token creation.
3. AI Classification & Discrepancy Detection NLP Urgency Engine
Evaluates complaint natural-language text against category lexicons and hazard keywords (e.g., exposed wires, severe flooding near schools). Computes priority levels (Low, Medium, High, Critical). If citizen manual selection conflicts with AI prediction, the discrepancy is automatically flagged for administrative review.
4. Evidence Ingestion & Inspection Flow uploadMiddleware.js
Implemented a robust file upload middleware powered by Multer with strict disk storage limits (5MB) and MIME-type filtering. Supports initial citizen photo submission during complaint creation as well as post-resolution proof photo attachments uploaded by municipal officers during the closure transition.

Edge-Case Hardening & Failure Recovery Mechanisms

Fault-Tolerant System Engineering

⚡ AI Engine Downtime

If classification microservice times out, the submission is saved with manual category and flagged as pending_classification. A background retry job triages without blocking the citizen.

📍 Missing Location Access

If browser GPS is blocked, system avoids corrupting database with dummy (0,0) coordinates. Accepts manual address while keeping coordinates null to protect duplicate geo-clustering.

🔄 Rapid Double-Submission

Debounce guards and client-side lockouts detect rapid duplicate button taps, binding the user to the existing registered ticket instead of inserting duplicate database records.

Database Architecture & Schema Collections

MongoDB / Mongoose ODM Schemas

📦 Complaint Entity Schema

  • complaintId: Unique sequential string (SC-2026-0001).
  • title, description, category: Indexed civic descriptors.
  • status: Enum [Submitted, Under Review, Assigned, In Progress, Resolved, Closed].
  • location: Ward, address, and GeoJSON coordinates (lat/lng).
  • images, resolutionImages: Paths to verified evidence files.
  • timeline[]: Chronological audit transitions with actors and remarks.
  • feedback: Rating (1-5★), review text, and citizen submission date.

👥 Supporting Collections & Relations

  • User: Base identity with email, bcrypt password hash, and role type.
  • Citizen: Profile extended with ward, phone number, address, and history.
  • Department: Name, department code, nodal officer, and SLA targets.
  • Notification: Recipient reference, complaint link, unread boolean flag.
  • Setting & SupportTicket: Configuration baselines and helpdesk tickets.
  • seed.js: Automated database initialization for test and demo data.

Final Phase Deliverables & Technical Risk Mitigations

📌 Deliverables for Final Submission

  • AI Duplicate Detection Service: Fast-API Python microservice using vector embeddings to flag duplicate civic complaints.

🛡️ Technical Risks & Architectural Mitigations

  • Risk: Spatial Query Latency on Map Pins
    Mitigation: 2dsphere indexing on MongoDB coordinates combined with viewport bounding-box query limits.
  • Risk: High Volume Submission Collisions
    Mitigation: Atomic counter sequences and optimistic retry handlers guarantee ID uniqueness.
  • Risk: Storage Overhead from Proof Photos
    Mitigation: Strict 5MB Multer caps with sharp image optimization pipeline scheduled before cloud backup.
  • Risk: Unhandled Client Token Expiration
    Mitigation: Centralized Axios/Fetch interceptor triggers automated logout and session modal prompt.
